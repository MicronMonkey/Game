# 請 Claude 依照此指令直接開發

你是資深 HTML5 遊戲製作人、Phaser 3 工程師、2D 美術與 UI/UX 設計師。請完整讀取本交接包的 `README_請先閱讀.md`、`docs/`、`config/`、`wireframes/`、`references/`，然後**實際建立可執行的遊戲專案**，不是只給大綱、假畫面、偽代碼或 TODO。

## 必達成果
打造《12:30！雙城集結令》（12:30 — Two Cities, One Voice），手機直式優先、桌面適配的 Phaser 3 + Vite + JavaScript ES6+ 網頁遊戲，可部署 GitHub Pages。四幕：午休集結→雙城同步→陽光 Boss 戰→11/13 真實紀錄。必須真的能選人、移動、引導、計分、觸發事件、施放技能、Boss 命中與扣血。遊戲分數、角色及障礙是虛構的遊戲化呈現。

### 絕對必要：照片結局
Boss 成功、Boss 失敗及前面任務未達標時，**都必須能看到相同完整的桃園和台中真實照片相簿**；首頁也能直接開啟相簿。若未提供真實照片，顯示「真實活動照片整理中」，不得補造、冒充或用 AI 圖作為當日紀錄。照片應從獨立 JSON 配置載入，加入後免改主程式。

### 技術及可靠性
請在新建 `game/` 目錄中完成開發，不得覆蓋任何既有遊戲；以獨立 localStorage key 儲存成績。請實作成功/失敗路徑、自動/手動暫停、避免重複計分、音效開關與瀏覽器音訊解鎖、手機安全區與觸控避免網頁捲動、圖片載入回退、Web Share/PNG fallback。以設定檔集中管理數值。尊重減少動態效果偏好。

### 執行順序
1. 先列出閱讀到的所有文件及已確定的需求，建立工程架構。
2. 做出可玩的雙城移動與引導（觸控 + 鼠標），親自執行測試。
3. 完成突發事件、技能、連擊和兩階段進度。
4. 完成可操作的 Boss 戰、勝敗分支、最終動畫。
5. 完成相同的照片結局、相簿與可下載成績卡。
6. 完成角色/場景/動畫/音效、手機適配、效能優化。
7. 編寫 README、`npm install`、`npm run dev`、`npm run build`、GitHub Pages 部署方式，執行驗收測試並列出結果。

### 不得以假實作充數
如果缺美術素材，請使用自己繪製的程序化圖形、Canvas 或授權可用資產建立一致的風格，**但真實紀錄照片不能假造**。如執行環境不可用，清楚列出限制和哪些項目未驗證，不得宣稱已完成測試。

### 交付輸出
完整原始碼、可部署 build、使用/更換照片的明確步驟、可編輯設定檔、測試結果與已知問題。所有功能需依 `docs/07_測試與驗收.md` 驗收。請先實作再回報，避免只提出計畫。
