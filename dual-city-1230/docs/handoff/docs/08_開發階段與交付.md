# 08｜實作順序與交付定義

## 建議七階段
1. **可運行基底**：專案建置、選單、場景切換、佔位程序美術、基本操作。
2. **核心 MVP**：兩地角色生成/選取/路徑/計分、倒數與簡易關卡結算。先實測操作樂趣。
3. **玩法深化**：角色差異、事件/技能/CD/Combo、難度與平衡。
4. **Boss**：弱點/光束/碰撞/血量/動畫/勝敗；勝敗分支都能進相簿。
5. **紀實相簿**：JSON、滑動/燈箱/破圖回退、分享卡、首頁直達；等到照片獲授權才加入正式內容。
6. **美術與品質**：精緻角色與場景、音效、教程、可及性、FPS。
7. **驗收與部署**：測試、README、build、GitHub Pages。

## 各階段完成標準
階段 2 前不可把只有可點按鈕的 Prototype 當成可玩遊戲。階段 4 前不得聲稱 Boss 已完成。階段 5 不得使用 AI 生成照片替代真實紀錄。階段 7 必須有實際 build 及完整 QA；未驗證要註明。

## 對 Claude 的進度回報格式
每階段回報：修改的檔案、可玩的新功能、實際測試命令/結果、已知問題、下一階段。可先交付功能正確的簡易美術，最後再精修，不要先花全部時間做只有外觀的首頁。

## 建議最後交付
- `game/` 完整來源、`dist/` 可部署產物、README、編輯照片教學、設定文件。
- 專案與《全民抓法克》完全獨立；不覆寫原網站；若放 GitHub 同網站，使用獨立路徑例如 `/dual-city-1230/`。
- 一份完整上線前人工檢查表（相簿授權、文案、照片人物識別、路徑、瀏覽器）。
