# 05｜真實照片結局與資料治理（最高優先級）

## 不能妥協的產品規則
1. Boss 成功 → 成功過場 → 真實相簿。
2. Boss 失敗 → 失敗過場 → **同一份真實相簿**。
3. 第一、二幕未達標 → 仍能挑 Boss，最後仍看相簿。
4. 首頁按「11/13 真實紀錄」 → 不必玩遊戲直接看相簿。
5. 桃園、台中各自完整展示，任何一組缺照也不能擋住另一組。
6. 尚未收到照片 → 顯示「真實活動照片整理中」，不使用假圖、AI 生成圖或海報代替紀實照片。

## 結局畫面節奏
- 第一屏：`2026.11.13｜桃園 × 台中`、標題「這一天，我們站在一起。」、副標「不同地點，同一時間，同一份信念。」
- 第二屏：桃園真實照片相簿，2–5 張為佳；保留全圖比例，左右滑/箭頭、可點開燈箱。
- 第三屏：台中真實照片相簿，同樣操作；無論成功失敗顯示內容一致。
- 結尾：「遊戲有輸贏，團結沒有終點。」／「謝謝每一位在 11/13 留下身影的夥伴。」
- 按鈕：再玩一次、分享遊戲成績、回到首頁、觀看完整真實相簿。

## 文案精確規則
成功過場：「陽光照進黑箱！」／「雙城的光，匯聚成希望。」
失敗過場：「黑箱尚未融化，陽光不會停止。」／「下一次，我們會帶來更多光。」
無論結果，相簿標題與照片**完全相同**，不要根據遊戲成績重新排序、隱藏或扣圖。

## 資料/資源規格
照片 JSON 使用 `config/event-photos.example.json` 為範例，實際部署複製到 `public/data/event-photos.json`。含 `taoyuan`、`taichung` 陣列；每張有 `src`、`caption`、`credit`、`alt`。新照片以 `public/assets/photos/<city>-NN.webp` 上架，需確認 JSON 路徑與 Vite base path 一致。圖像使用自然比例與 `object-fit: contain`，保留人物。懶載入、載入錯誤/空陣列回退、左右滑、鍵盤操作、燈箱、進度點。

## 權利、準確性、隱私
- 只放經照片持有人許可、適合公開張貼的照片；辨識度高人物應確認適當肖像使用同意，必要時遮蔽臉部/識別證/車牌/內部文件。
- 不上傳照片 EXIF 精確位置，公開檔案前移除不必要中繼資料。
- 不把當天事件不確定的細節當成官方史實。可用「11/13 活動照片」等中性描述。
- 真實照片與遊戲插畫分資料夾，明確標示「活動紀錄／遊戲虛構畫面」。
- 海報僅是使用者提供的設計/事件參考，不預設具備所有內容的獨立再利用權利；如要在遊戲內原樣公開，需確認相應權利。
- 成績分享卡建議使用自製插畫，避免用未授權現場照片製圖。

## 尚未收到照片的驗收
應可啟動相簿頁、顯示兩區待更新狀態；即使 JSON 缺少一城或個別 URL 404，也可繼續操作並能返回首頁。
